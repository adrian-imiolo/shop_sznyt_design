# ProductForm owns fields, validation, and submit; the backend gets a guard, not a second validator

`AdminAddProduct.tsx` and `AdminEditProduct.tsx` hand-duplicated the same 7-field product form — identical state shape, labels, classNames, and try/catch/`ApiError` submit lifecycle — and neither had a test. `price`/`stock` were plain `type="text"` inputs run through a bare `Number(...)` at submit, so a natural Polish decimal comma ("149,99") produced `NaN`, reached Prisma (`price Float`, `stock Int`) as a type error, and surfaced as an opaque 500 that named no field. Extracted into `src/pages/admin/ProductForm.tsx` plus a pure `productFormValidation.ts`; both pages are now wrappers. Grilled with Adrian, 2026-09-10 (issue #162, part of map #159).

Decisions and why:

- **One module owns rendering *and* the submit lifecycle — no companion hook.** `usePublicForm.ts` earned its hook seam because two different forms (contact, zwroty) with different field sets share one submit lifecycle. Here the lifecycle has exactly one consumer — `ProductForm` itself — so a hook would be a seam nothing varies across. Fields, validation, loading/error state, and the API call sit behind a single component interface.
- **That interface is one optional `product` prop.** Create vs update, POST vs PUT, the heading, the submit label, the initial values, and the `String(price)` conversion all derive from its presence, so neither caller names a REST verb or a URL. `AdminAddProduct` is four lines.
- **Editing mounts the form only once the product has loaded.** `product` seeds `useState` at mount and is never re-read, which deletes the `useEffect` that used to backfill fields when the fetch landed. Same technique #160 used for `ProductsTable` — hold the mount instead of syncing late-arriving props.
- **`validateProductForm` returns either the parsed payload or field errors, never both.** A discriminated union (`{ ok: true; payload } | { ok: false; fieldErrors }`) means no caller can end up holding a `NaN` payload — the type makes the old bug unrepresentable rather than merely unlikely. Errors accumulate across fields so one submit reports every bad field.
- **Comma decimal input is accepted, not rejected.** `formatPln` renders every price in the app with a comma separator, so demanding a dot on input would contradict what the admin reads on every other screen. Price normalizes `,` → `.` before parsing. This is also why price/stock stay `type="text"`: a native `type="number"` silently rejects the comma we just decided to accept.
- **Rich validation on the frontend, a bare guard on the backend.** The product routes sit behind `requireAuth` + `requireAdmin`, so — unlike the public forms in `routes/forms.js`, which guard against the open internet — the realistic bad input is an authenticated admin's typo. That's a UX problem, answered inline with per-field Polish messages. The backend adds only `numericFieldError()`: a present-but-non-numeric `price`/`stock` answers 400 naming the field, instead of `NaN` dying in Prisma as a 500. Deliberately not a second implementation of the frontend's rules. `undefined` still passes, because PUT reads it as "leave this column alone".
- **That guard demands a real number, not a numeric string.** Accepting `"149.99"` would only move the failure — Prisma rejects a string for a `Float` — and no legitimate caller sends one.
- **Add gains the heading and the Cancel link it never had.** The two pages differed only by accident: Add had no heading, no way out but browser-back, and a full-width button. Both now share one chrome. The submit button also disables while in flight, matching ADR-0005's "disable where pausing costs nothing" — on the create path a double-click otherwise creates two products.
- **The reset-before-navigate is dropped from both pages.** Each blanked `formData` immediately before `navigate("/admin")`; the component unmounts either way, so it never had an observable effect.
- **No component test.** This codebase has no component-render tests and no `@testing-library/react`; every suite targets pure logic. The extracted validator is tested directly, the backend guard through the existing HTTP suite, and per ADR-0005 a wrapper with no logic past the interface doesn't earn one.

Consequence: a malformed price now names its own field on both sides of the wire, and the next admin form starts from `ProductForm`'s shape instead of a third hand-rolled copy.
