# Eyebrow owns the label identity for all 29 callsites; the ml-1 nudge stays opt-in because it is size-calibrated

The eyebrow label — small uppercase accent text above a heading or a block of content — was hand-written 29 times across 14 files, every one a `<p>` whose class core was byte-identical (`font-dm-sans text-xs text-accent tracking-[0.3em] uppercase`), varying only in trailing spacing. That duplication had already shipped a bug: #156 added `ml-1` to `ProductDetail.tsx`'s eyebrow to close an optical gap, missed the identical eyebrow/heading pair in `ProductSection.tsx`, and #157 had to re-fix it minutes later. Extracted into `src/components/Eyebrow.tsx`. Grilled with Adrian, 2026-09-10 (issue #164, part of map #159).

Decisions and why:

- **One module for all 29, not two siblings.** The callsites split into two real populations: 18 kickers above Cormorant type, and 11 field/section labels above DM Sans body content (`OrderCard`'s four, `Contact`'s `Email`/`Czas odpowiedzi`/`Pomocne linki`, `Cart`'s `Dostawa`, `FAQ`'s category, `About.tsx:57`). They still collapse into one module, because the thing being centralised *is* the identity string — splitting it across an `<Eyebrow>` and a `<TitleEyebrow>` would put that string in two files and re-open precisely the seam this closes. Cormorant-adjacency is a context, expressed as a prop.
- **`alignsWithHeading` is opt-in, and the other 16 kickers deliberately don't get it.** This is the decision most likely to look like an oversight later, so: #156's own commit message says the nudge compensates *"Cormorant Garamond's display-size letters"*, and left bearing scales with font-size. The two callsites carrying `ml-1` are the only two in the codebase whose heading is exactly `text-3xl md:text-4xl lg:text-5xl`. The other 16 sit above headings from `text-xl` to `text-7xl`, where a constant 4px would over- or under-correct. Making the module own `ml-1` unconditionally would therefore have been a 16-callsite *visual change* dressed up as a refactor. Whether those callsites want their own per-size values is a real question, left to its own ticket where it can be judged in a browser.
- **The prop is `spacing?: string`, not `className`, and not a token union.** Seven distinct values are live, including `About.tsx:57`'s responsive `mb-8 md:mb-16` — a union of single utilities cannot express that, and widening it to seven tokens would be a `className` passthrough with extra ceremony. A free string keeps every callsite byte-identical. Naming it `spacing` rather than `className` (as `Skeleton.tsx` does) preserves the mechanism while making an identity override — `text-sm`, `text-warm-white` — read as obvious misuse at the callsite. Tailwind wouldn't honour such an override reliably anyway: equal-specificity utilities are resolved by order in the generated stylesheet, not order in the attribute.
- **Extracting the eyebrow+heading *pair* was considered and rejected.** A `TitleBlock` owning both elements is the only shape that makes the #156/#157 bug structurally impossible, since alignment would become internal. But the 18 kickers vary by heading level (`h1`/`h2`/`h3`, and two plain `<p>`s), size ramp, and trailing classes, so most of that variety would land in the interface — a shallow module with a large surface. The guard test covers the realistic recurrence path at a fraction of the cost.
- **The guard test, not the module, is what prevents recurrence.** Extraction removes today's 29 copies; it does nothing about the 30th. `Eyebrow.test.tsx` scans `src/` for the identity triple in any `className` outside the module and names the offending file. It was verified non-vacuous by reintroducing the old markup and watching it fail.
- **First `.test.tsx` in the codebase, still with no new dependencies.** `renderToStaticMarkup` from `react-dom/server` runs in the existing node-environment vitest suite, so asserting the exact rendered class attribute needs neither `jsdom` nor `@testing-library/react`. This supersedes the reasoning in ADR-0006 and #162 that a component here is untestable: what those cases lacked was testable *logic*, but a module whose entire job is producing one class string has that string as a genuine interface. It does not follow that render tests are now wanted for components with real behaviour — that would still need the missing tooling.
- **Verified by screenshot diff rather than by chrome-devtools.** The MCP server has failed to connect for three sessions running. Playwright is already a devDependency, so ten affected routes were screenshotted at 1522×672 full-page on `main` and again on the branch: all ten PNGs byte-identical, covering 25 of the 29 eyebrows. `OrderCard`'s four sit behind Clerk auth and rest on the module's own tests.

Consequence: the eyebrow's identity now has one home and a test that keeps it there, and the open question of optical alignment for the other 16 kickers is recorded as a question rather than silently answered with a wrong constant.
